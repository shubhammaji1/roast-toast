## B. Detailed bug tracker

All findings below remain open. Environment defaults to Windows / Chromium 156.0.8078.4 / 1440×900 / fresh anonymous visitor. Evidence paths are local and relative to this report. [Download CSV](../.data/audit-2026-11-16/bug-tracker.csv).

### RT-01 — Live browser ownership cookie lacks Secure (P2)

- **Route:** /saved (shared session)
- **Preconditions:** Fresh anonymous visitor on the live deployment.
- **Reproduce:** Open a fresh browser context, visit /saved, inspect cookie attributes; repeated in a second fresh context.
- **Expected:** The HTTPS deployment issues a Secure, HttpOnly ownership cookie.
- **Actual:** rt-visitor: secure=false, httpOnly=true, sameSite=Lax. The expected production __Host- name is absent.
- **Impact:** The browser identity grants ownership. Cookie transport protection is weaker than the code’s intended production configuration. HTTPS/HSTS mitigates risk; no theft or exploit was attempted.
- **Root cause:** Verified source: apps/api/src/visitors.ts chooses name and Secure from NODE_ENV. A non-production API environment or deployment mismatch is a hypothesis; hosting settings were not accessed.
- **Fix:** Verify the deployed API environment and production startup checks, issue Secure cookies for HTTPS, and preserve/review existing identity migration before changing cookie names.
- **Evidence:** [verification.json](../.data/audit-2026-11-16/verification.json)
- **Status:** Open — confirmed twice

### RT-02 — Footer Pitch an idea link has insufficient text contrast (P2)

- **Route:** All 17 audited routes
- **Preconditions:** Fresh anonymous visitor on the live deployment.
- **Reproduce:** Open / at 1440×900, scroll to footer, run axe color-contrast or inspect computed colors.
- **Expected:** At least 4.5:1 for the 10px normal-weight text (WCAG 1.4.3).
- **Actual:** #fffaf1 on #e26442 measures 3.29:1.
- **Impact:** Shared primary footer action is harder to read for users with low vision.
- **Root cause:** Verified computed colors on .footer-cta; shared footer styling in apps/web/src/app/globals.css.
- **Fix:** Use a darker button background or darker text with a measured ratio >=4.5:1; retest normal, hover and focus states.
- **Evidence:** [home-1440.png](../.data/audit-2026-11-16/home-1440.png)
- **Status:** Open

### RT-03 — Footer brand link fails automated label-in-name check (P3)

- **Route:** /; also confirmed /new and /saved, shared footer
- **Preconditions:** Fresh anonymous visitor on the live deployment.
- **Reproduce:** Run axe with wcag21a on /. Inspect footer link visible text and aria-label.
- **Expected:** Accessible name contains the visible label (WCAG 2.5.3).
- **Actual:** Visible roast & toast. versus aria-label Roast and Toast home; axe label-content-name-mismatch fails.
- **Impact:** Potential voice-control mismatch. Automated finding is confirmed; actual speech recognition impact has not been tested.
- **Root cause:** Verified explicit aria-label in apps/web/src/components/shell.tsx.
- **Fix:** Preserve the visible brand text in the accessible name, or remove the unnecessary override. Confirm with axe and speech input.
- **Evidence:** [supplemental.json](../.data/audit-2026-11-16/supplemental.json)
- **Status:** Open — assistive-technology validation pending

### RT-04 — Public policy pages still declare unfinished launch prerequisites (P1)

- **Route:** /privacy and /terms
- **Preconditions:** Fresh anonymous visitor on the live deployment.

- **Expected:** Before a public production launch, the site’s own stated operator details and policy review are complete.
- **Actual:** Pages explicitly identify development drafts and missing operator identity/contact, retention information and review.
- **Impact:** Users cannot find complete operator accountability and data-handling information. Release-readiness blocker under the site’s stated requirements; this is not a legal compliance opinion.
- **Root cause:** Verified draft content in apps/web/src/app/privacy/page.tsx and terms/page.tsx.
- **Fix:** Have the operator supply the missing facts and finalize reviewed notices before inviting public use. No fabricated operator details.
- **Evidence:** [privacy-1440.png](../.data/audit-2026-11-16/privacy-1440.png)
- **Status:** Open

### RT-05 — Long searches expose a technical validation message (P3)

- **Route:** /explore
- **Preconditions:** Fresh anonymous visitor on the live deployment.
- **Reproduce:** Enter 500 x characters in Search ideas and press Enter.
- **Expected:** A clear length limit or concise field guidance while retaining search controls.
- **Actual:** Results become Something didn’t go through / Too big: expected string to have <=100 characters / Try again. Retrying the same query cannot succeed; clearing it recovers.
- **Impact:** Confusing recoverable search failure; no crash or unsafe HTML execution observed.
- **Root cause:** Input accepts more than the API’s 100-character constraint; server validation wording is rendered directly.
- **Fix:** Match the input limit to the domain contract or show a field-level message: Search using 100 characters or fewer. Retest clearing and shortening.
- **Evidence:** [long-search-390.png](../.data/audit-2026-11-16/long-search-390.png)
- **Status:** Open — behavior characterized

### RT-06 — Routes share a generic document title and lack canonical links (P4)

- **Route:** All 17 audited routes
- **Preconditions:** Fresh anonymous visitor on the live deployment.
- **Reproduce:** Navigate directly to /about, /new and /privacy; inspect document.title and link[rel=canonical].
- **Expected:** Meaningful route-specific titles and intentional canonical metadata where appropriate.
- **Actual:** One common title across all audited routes; no canonical link in captured metadata.
- **Impact:** Reduced tab/history identification and search metadata quality. Canonical absence alone does not demonstrate duplicate indexing.
- **Root cause:** Shared layout metadata; no route-specific override observed.
- **Fix:** Add route titles and intentional canonical URLs in apps/web/src/app route metadata.
- **Evidence:** [live.json](../.data/audit-2026-11-16/live.json)
- **Status:** Open

### RT-07 — Mobile lab LCP misses the requested 2.5-second target (P3)

- **Route:** /; /explore; /new; /saved
- **Preconditions:** Fresh anonymous visitor on the live deployment.
- **Reproduce:** Run Lighthouse 12.8.2 with default mobile simulated throttling, 390×844 CSS viewport and DPR 3, on each listed route.
- **Expected:** Requested engineering target: LCP <=2.5 seconds and performance score >=90.
- **Actual:** Quieter reruns measured LCP 2.75–2.89 seconds and performance scores 81–85. Desktop reruns scored 98–100.
- **Impact:** Mobile visitors may wait longer for primary content. These are lab samples, not field p75 or proven real-device impact.
- **Root cause:** Not isolated. Lighthouse reports main-thread/JavaScript and render-path opportunities; profile individual resources before assigning cause.
- **Fix:** Take repeated isolated mobile measurements, inspect the LCP element and blocking work, then optimize the measured critical path and retest.
- **Evidence:** [performance-final.json](../.data/audit-2026-11-16/performance-final.json)
- **Status:** Open — measured target gap; field confirmation pending

## E. Accessibility and security observations

The broad 17-route axe scan covered WCAG 2 A/AA, 2.1 AA and 2.2 AA tags; it omitted the 2.1 A tag. A supplemental scan on /, /new and /saved included that tag and found RT-03. Therefore do not interpret the first scan as full WCAG 2.2 coverage. Contrast RT-02 appeared across all 17 routes. The local suite's axe check also found RT-03. No claim of accessibility conformance is made.

- [WCAG 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html): normal text generally needs 4.5:1; fix RT-02's 3.29:1.
- [WCAG 2.5.3](https://www.w3.org/WAI/WCAG22/Understanding/label-in-name.html): accessible names should contain visible labels; resolve RT-03 and confirm speech-input behavior.
- Skip-link focus and keyboard detail-tab movement were exercised. Full screen-reader announcements, focus traversal across every control, contrast for every state, complete target-spacing audit and final dialog focus restoration were not completed.
- Live headers include HSTS, X-Content-Type-Options nosniff, X-Frame-Options DENY, Referrer-Policy and Permissions-Policy. No CSP was captured; this is a hardening observation, not proof of exploitable XSS.
- RT-01 is independently reproduced. [Cookie Secure documentation](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie) explains that Secure restricts transport to HTTPS. Do not infer theft from its absence; HSTS is present.
- API tests exercised ownership, privacy, origin rejection and moderation checks in isolated PostgreSQL. No production brute force, exploits, hostile scans or data extraction occurred. Production environment variables, secret exposure across every bundle and backend infrastructure were not audited comprehensively.

## G. Fix priority roadmap

1. **Before release:** RT-04 operator/policy completion; investigate RT-01 production cookie/environment mismatch and verify fresh/returning browser ownership after remediation. Review production startup safeguards before changing deployment configuration.
2. **Next release:** RT-02 contrast with shared-footer regression scans. Confirm production security parity with the isolated ownership/draft tests. Address mobile performance results exceeding measured targets.
3. **Quality improvements:** RT-03 accessible name/speech test; RT-05 search field guidance and recovery; fix resize test synchronization by waiting for settled geometry instead of sampling during the 200ms margin transition. Preserve the original failure record.
4. **Polish:** RT-06 route metadata; evaluate indexing policy when the site moves from development to public launch. Add deterministic visual baselines after fixture and font state are stable.

Suggested owners: deployment/API for visitors.ts; frontend for globals.css, shell.tsx and feed.tsx; operator for privacy/terms; QA for viewport synchronization and browser/device coverage. Regression dependencies: disposable seeded database, fresh browser contexts, approved moderator account, and a known deployment revision. No automatic deployment or content changes were made.

## H. Final release decision

**NOT READY FOR RELEASE.** The site explicitly identifies unfinished public-launch policies, the deployed ownership cookie differs from the intended secure production configuration, and shared accessibility findings remain open. Core isolated workflows and the broad overflow sweep are encouraging evidence, but they do not override those findings or the documented coverage limits. Reassess after the fixes and targeted regression tests above.
